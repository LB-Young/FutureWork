# 创建 FutureWork Skill

参考 Bamboo 的 skill-creator 思路：先明确用途与触发边界，再写精简的执行说明；把长资料放在按需读取的资源中。Skill 是方法说明，本身不授予工具、模型、文件或网络权限。

## 何时使用

- 用户要求创建一个可重复使用的技能，或改进、审查已有 Skill。
- 用户希望把某项稳定的领域知识或工作流程封装为 Skill。

普通问题、一次性任务、仅查看已有 Skill 时，不要创建新 Skill。

## 创建步骤

1. 确定技能服务的重复任务、适用条件和不适用条件；需求不完整时先补足关键约束。
2. 选用小写字母、数字和连字符组成的短 ID，并写出准确描述。不要起笼统的名字。
3. 编写行动步骤和每步验收方式。只写执行者需要遵循的特殊约定，避免堆砌通用知识。
4. 调用 `skill_create`，把 ID、触发描述和说明保存到用户目录 `~/.FutureWork/abilities/skills/<ID>/`。工具调用需要用户审批，不得声称未经审批已安装。
5. 如需脚本、参考资料或模板，在该技能目录下按需添加 `scripts/`、`references/`、`assets/`；脚本须独立审查和授权，不能因为加载 Skill 就执行。
6. 检查 `SKILL.md` 的名称、描述、触发边界、步骤和文件路径；再为目标 Agent 的 `[extensions] skills` 显式添加 Skill ID，按其工具权限实际验证。安装与启用是两件事。

## 质量检查

- 描述同时说明何时使用和何时不使用；正文能指导实际执行。
- 不把密钥写入 Skill；不暗示 Skill 绕过审批或授予工具权限。
- 长资料按需读取；重复经验可以写入用户技能目录，但不要污染包内只读资源。
- 已存在的技能先检查和修改，不要用同名创建工具覆盖用户内容。
